### `basement/006-cognitive-closure-concept.md` — 认知闭包概念定义

### `basement/007-cognitive-closure-acquisition-optimization.md` — 闭包获取的工程优化

认知闭包体系的第二篇。形式化闭包获取为优化问题 `min |M| s.t. N ⊆ M`——在保证 N 完整出现前提下，实际上下文 M 越小越好。分析 M>N 的三个冗余来源（加载粒度/导航开销/探索性），列出五种获取策略（从全量加载到 trace+xpath 精确加载），指出务实路径（先策略5 trace缩小+AI提炼，再向策略4 trace闭包遍历演进）。关键洞察：trace 的真正价值是缩小 M 到 AI 能可靠提炼的规模，不是精确给出 N。

**覆盖问题场景**：
- 理解如何高效获取认知闭包
- 理解 trace 的真正价值（缩小 M 而非精确 N）
- 规划闭包获取工具的改进方向（闭包遍历算法/xpath行范围映射/read支持xpath）
- 理解起点明确性和 M 大小的关系（akash 阶段1的价值）

**依赖关系**：前置 `basement/006-cognitive-closure-concept.md`。复杂 N 的迭代逼近见 `basement/008-cognitive-dynamic-process.md`

### `basement/008-cognitive-dynamic-process.md` — 认知动力过程

认知闭包体系的第三篇。处理 007 的隐含假设（N 可一次提炼）在复杂工作包中不成立的问题。提出迭代逼近模型：n1→n2→…→N，多代认知包逐代逼近。核心区分：n[x] 不是 M——n[x] 是关于"N 是什么"的带证据候选集（假设），M 是进入上下文的原始内容。强调非单调性是精髓（成员进进出出反映认知逼近真相），每代必须记录纳入/排除理由。收敛判据 n[x]=n[x+1]。⚠️ 收敛判据有根本性缺陷（由 009 识别）。

**覆盖问题场景**：
- 理解复杂工作包为什么需要多代逼近
- 理解认知包 n[x] 和上下文 M 的本质区别
- 设计认知包持久化机制（cognitive-pack.md，跨 session 传递）
- 判断什么时候需要认知动力过程（trace链深度>3层/跨多分类法/序贯依赖）

**依赖关系**：前置 `basement/006`、`basement/007`。根本性缺陷修正见 `basement/009-island-cognitive-crisis.md`

### `basement/009-island-cognitive-crisis.md` — 孤岛认知危机

认知闭包体系的第四篇，008 的根本性缺陷修正。识别出 008 的收敛判据只能保证连通分量内完备——如果 trace 关系图有多个连通分量（岛屿），从起点所在岛屿出发永远到不了其他岛屿，收敛判据照样满足但 N 不完备。解法：用目录结构作为不依赖 trace 的 fallback 分类学，递归遍历所有子目录的 README。精髓是"套娃"——孤岛在任何套娃层次都可能出现，要求每个子目录都有 README。对 008 增加阶段0（岛屿遍历）。

**覆盖问题场景**：

### `basement/010-trace-idempotency-practical-boundary.md` — trace 幂等的实用边界

认知闭包体系的第五篇，006-009 共同依赖的基础设施定义。澄清 trace 幂等不是"所有可追溯的都追溯"的无限制幂等，而是在实用粒度上的幂等。粒度决策原则："这个粒度上的关系，对理解和工作有意义吗？"——代码函数级有意义，行级没意义；DB 表级有意义，记录级通常没意义。三个判定维度：影响性/可定位性/独立身份。幂等两层含义：关系完备性 AND 粒度合理性。幂等的实用价值检验 = query 一个 checkpoint 能否得到完整关系图。

**覆盖问题场景**：
- 理解 trace 幂等的精确含义和实用边界
- 判断各资产类型应该追溯到什么粒度
- 理解幂等的实用价值检验（checkpoint 关系图）
- 为 trace_verify.py 配置粒度决策

**依赖关系**：前置 `basement/006-009`。文档形态见 `basement/011-cognitive-closure-document-form.md`

### `basement/011-cognitive-closure-document-form.md` — 认知闭包与认知包的文档形态

### `basement/012-cognitive-pack-deliverable-and-co-visibility.md` — 认知包交付包与协同可见性困境
