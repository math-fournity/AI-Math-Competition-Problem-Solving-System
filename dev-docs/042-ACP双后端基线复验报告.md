## 四、基线事实（供 U2–U8 认知加载引用，自包含）

1. **双后端本机可用**（2026-08-21 实测）：initialize→session/new→prompt 全链路通；
   OpenCode 用 `--cwd` 定工作区，Devin 用 `--model` 参数。
2. **协议 v1 双方一致**：mcpServers 必填（空数组可）、session/prompt 为 request-response
   语义——但 **OpenCode 实际不回 response**，完成检测走"静默窗口（30s 起步，U5 实测定值）"
   或状态查询；Devin 走 stopReason。
3. **thinking 流式双方可用**：agent_thought_chunk 实测有数（OpenCode 485/Devin 10，
   随任务变化）；内容为单词级分片拼接。
4. **trajectory 来源三层**（038 §八）：通知 jsonl 实时落盘为主（本次冒烟 jsonl 即此形态：
   每行 {ts, dir, msg}）；OpenCode 有原生 `opencode export [sessionID]` 兜底；
   SQLite 直读不作主路径。
5. **冒烟脚本可扩展**：`scripts/test_wp_u1_acp_smoke.py` 参数化双后端——U2 的三路对比
   脚本在此基础上加数学题 prompt 与组装器即可。
6. **版本漂移常态**：引用 OpenCode 行为前先 `opencode --version`；行为异常先怀疑版本变化。
7. **权限**：OpenCode 靠 opencode.json `"*": "allow"` 零交互（bash 危险命令白名单 deny
   生效中）；Devin 需 client 实现 request_permission 自动响应（冒烟脚本已含实现，可抄）。
