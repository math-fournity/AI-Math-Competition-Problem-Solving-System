## §1 根因模型——为什么旧模式必败（决定新设计的每个选择）

1. **有损压缩税**：主控把数十万字符推理压成几KB结论清单。裸结论无法让接手者区分"严格证明"与"上轮可能的错误"，接手者唯一理性动作是重验——预算死在重验里。
2. **信任不可传递**：数学结论的可信度来自推导过程而非宣告。HANDOVER给不出过程（给了就等于没压缩），所以信任税不可避免——**除非接手者自己完成理解**。
3. **认知模式打架**："观察（理解已有）"与"解题（生成新推理）"是两种模式。同实例同回合混用，注意力互相挤压（实测：混合任务实例在预算后期倒退去重验早已闭环的内容）。
4. **thinking阶段无法写文件（架构性硬约束）**：模型的输出顺序是 thinking → message/tool_calls。output预算被extended thinking耗尽时，working阶段（唯一能写文件的阶段）永远不到达。因此"边想边写"指令天然无效——烂尾是常态，必须由编排兜底。
5. **截断不可协议检测**：opencode撞单响应output上限（实测32000）时stopReason仍报`end_turn`。只能靠指纹启发式（§6.3）。

## §2 角色与轮次类型（只有三种）

| 类型 | 输入 | 交付物 | 禁止事项 |
|---|---|---|---|
| **轮1·解题者** | 仅题目 | `工作笔记.md` + `proof.md`(若完成) | 无历史可读 |
| **轮N·观察者**（N≥2） | 前轮全部档案 + oc_traj工具 | **仅`分析笔记.md`** | **禁止解题推进**、禁止通读原文 |
| **轮N·解题者**（N≥2） | 最新`分析笔记.md`（一次通读） | 推进证明 + `工作笔记.md` + `proof.md`(若完成) | 不翻旧档案（除非核实笔记中某具体推导） |

**职责分离的铁律**：观察者不解题，解题者不考古。v1的失败实例全部死于两种模式混用。

### 2.1 两份文档的职责界定

- **`工作笔记.md`**：解题者的**过程性自我记录**。四节结构（已确认结论附推导要点 / 正在做 / 死路记录 / 下一步）。允许烂尾——thinking阶段无法写文件是架构性的，烂尾部分留在trajectory尾部，由下一轮分析笔记收殓。
- **`分析笔记.md`**：观察者对**紧邻前轮**（且仅紧邻前轮）的独立理解重构 = 前轮工作笔记 + 前轮thinking尾部（最后一次笔记更新之后、截断之前的进展——"遗言"）的整合。五节结构见§4.2。更早轮次不重复分析（递归链已覆盖）；对更早档案的修正记文末专节。

### 2.2 递归责任链

```
轮n的欠债只有一笔：轮n-1。
A(n) = 消化[ W(n-1) + tail(T(n-1)) ]    ——分析笔记（观察者产出）
W(n) = 自己的探索过程记录                 ——工作笔记（解题者产出）
T(n) = 本轮完整thinking                  ——原始档案（驱动器自动落盘）
```

原始档案永不删除。链条上任何一环被怀疑，接手者用oc_traj工具下钻任意深度验证。

## §4 提示词规范（三个模板全文要点+设计理由）

模板文件（主repo `poc_assets/poc_2.7.5/v2/`）：`prompt_round1.md`、`prompt_observer.md`、`prompt_solver.md`。以下为各模板的核心段落与**设计理由**（理由是灵魂——改提示词时不可丢）。

### 4.1 轮1·解题者（prompt_round1.md）

核心段落：
- "你是这道题的第一个解题者，在你之前没有任何人做过任何工作。"（角色锚定）
- 工作笔记四节结构 + **"写笔记的优先级高于多推一步算式"**
- "你可能会被截断。无须恐慌——只要你的工作笔记是最新的，后来者就能接上。"（消除恐慌性收尾）
- 防作弊条款（禁搜题面/禁翻档案/接触须声明）

已知限制：实测轮1仍全程thinking直到截断、零笔记产出（§1.4架构性约束）。**这是预期行为**——轮1的价值在于T1本身，轮2负责收殓。不要试图用更强措辞强迫thinking阶段写文件。

### 4.2 轮N·观察者（prompt_observer.md）

开场白采用用户的考古学叙事（**此段是提示词的灵魂，逐字保留**）：

> 这些是上一个AI探索这道题目最后的现场。你是轮次{ROUND_NUM}……它们都对它们之前轮次的所有AI的工作trajectory和相关产出做了分析，都留下了分析笔记，也都留下了自己的工作笔记。所有的细节都在trajectory中，所有的笔记都在各轮次目录中。上一轮次的AI最后的思考，不在它的笔记中，在它的trajectory的最后的thinking中，你可以通过脚本的参数来直接拿到。但是你要注意，在它的工作笔记的最后更新和它的最后一次thinking之间，它可能还做了其他的事，所以它的笔记只是一个索引。

核心段落：
- **预算纪律块（违反=任务失败）**："你的输出预算约32000 tokens。禁止通读任何thinking全文——上一轮实例就是试图通读65K原文而耗尽预算、一份笔记都没留下。"然后给出正确姿势四步：scan→tail→定点read→边分析边写。
- 分析笔记五节结构：题目与全局状态 / 当前前沿（**附推导要点，不是裸结论**）/ 死路清单 / 明确的下一步缺口 / 对更早档案的修正。
- 写作纪律："宁可少而准，不可多而糊。每个论断都要能让解题者直接使用。"

实证效果：R3/R5两轮专职观察者均成功产出（11742B / 更新版），R5还自主执行了历史欠账（暴力搜索）并发现跨轮笔误。

### 4.3 轮N·解题者（prompt_solver.md）

核心段落：
- "你不做档案分析——那已经由观察者完成。你只做一件事：从最新前沿继续推进证明。"
- "读`分析笔记.md`（一次，通读）。它就是你的全部上下文。读完直接开工，不需要翻查任何历史档案。"
- oc-trajectory工具仅在需要核实笔记中某具体推导时使用。
- 截断无须担心段（同轮1）。
- 防作弊条款。

实证效果：R4在纯解题模式下完成了v1五轮+主控都未攻下的(O,O,O)定理；R6在组装任务下正常COMPLETED。

## §6 驱动器规格（acp_v2.py，参考实现在主repo `v2/acp_v2.py`）

### 6.1 流程

```
1. 重建隔离区，复制 rounds/round{1..N-1} 进去
2. 组装prompt（按轮次类型选模板，填充轮次号）
3. opencode acp --cwd <隔离区> 启动
4. initialize → session/new → 断言×2 → session/prompt
5. 通知循环采集（thoughts/messages/tools三路jsonl实时落盘）
6. 终态判定 + 归档 + 监督摘要打印
```

### 6.2 两步断言（fail-fast，缺一不可）

```jsonc
// ① 设模型（方法名兼容探测：session/set_config_option 或 session/set_config）
// ② 断言响应回显 configOptions[id==model].currentValue == 所设值
// ③ 切模型后configOptions新增effort项 → set effort=max → 同样断言回显
```

**背景**（U1冒烟实证）：不显式设模型会落到内建默认`opencode/big-pickle`；ox-alpha的effort默认`low`。opencode.json里的`options.reasoning.effort`元数据**不会**生效到session运行时初值。断言回显是接受的唯一证据。任一断言失败立即中止。

### 6.3 完成检测（踩坑实录，三个参数都有尸体）

| 参数 | 值 | 尸体 |
|---|---|---|
| 静默阈值 | **300秒** | 初版30秒误杀R3首跑：工具间隙中的深度思考启动期无chunk输出，30秒即触发误判终止（当时它已完成分析宣布"现在一次性写入交接文档"，就差一个write调用） |
| pending tool放宽 | 600秒 | 工具执行中无chunk属正常 |
| 进程存活检查 | proc.poll() | 进程退出才算真结束 |
| 总时长保险 | 120分钟 | 兜底cancel |

### 6.4 实时落盘

thoughts/messages/tools三路jsonl**逐条flush**——进程崩溃不丢数据（export通道已证实不可靠，见§3.1）。

## §7 主控监督协议

主控（编排AI）每轮结束后的检查清单：

1. 断言回显存档核验（launch_assertions字段）；
2. 终态判定复核（截断指纹是否误判/漏判）；
3. 观察者轮：抽查分析笔记对thinking尾部的引用准确性；
4. 解题者轮：工作笔记是否有实质更新；是否发生重验倒退（重验已闭环内容的篇幅占比）；
5. 跨轮修正链是否工作（后轮对前轮笔误的发现与记录）；
6. 提示词缺陷记录 → 迭代模板 → 下轮验证。

**主控的红线**：不代推数学、不写HANDOVER、不因连续失败而收回推理权。主控的杠杆在提示词迭代——1962实验中五项编排迭代（静默阈值、指纹修正、角色拆分、供料替代禁令、预算配速）全部来自监督观察。
