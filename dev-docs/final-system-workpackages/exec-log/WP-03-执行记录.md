## 四、稳定接口

### prompt 渲染

`src.prompt_contract.render_prompt(role, values)` 支持：

- `round1`：`ORIGINAL_PROBLEM`；
- `observer`：`ROUND_NUM/PREV_NUM/ORIGINAL_PROBLEM/PREV_ROUND_DIR/`
  `PREV_WORK_NOTES_PATH/MAP_PATH/EXPORT_PATH/NOTES_PATH`；
- `solver`：`ROUND_NUM/PREV_NUM/ORIGINAL_PROBLEM/NOTES_PATH/ROUND_DIR`。

缺字段、额外字段、模板占位符漂移、渲染后遗留占位符都直接报错。接口不连接 DB/Redis。

### 每轮资产

规范目录覆盖 prompt、role/model/backend 元数据、ACP notifications/thought/message/tool 实时流、
conversation/map、工作/分析笔记、proof/partial、formal源码/说明/log、verification脚本和
round_result。合同同时规定 mtime/路径归属、逐条 flush、永不覆盖、先收资产后释放 lease。

## 五、1962 离线 fixture

`tests/fixtures/1962/` 有五个场景：

1. v1 裸 HANDOVER 对照；
2. R2 现场到 R3 observer；
3. R3 notes 到 solver，聚焦 OOO 而不重做 EEO；
4. R4 现场到 R5 observer，复核新定理/执行欠账/修正笔误；
5. R5 notes 到 solver，组装、自查和验证资产归档。

fixture 是人工去答案、符号化现场，不含最终四组答案、最终 proof 或 `/Users/...` 外部资产
路径。普通回归不在线调用模型；真实模型实验须隔离复制单个 scene，并由 WP-10 记录成本和
模型配置。
