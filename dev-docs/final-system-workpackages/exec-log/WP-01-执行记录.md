## 一、结果

当前 legacy launcher 和独立 v2 管线均不再把固定 Round 数写成新的永久失败：

- `round_window_size` 表示本次调度窗口数学 Round 额度；
- 窗口用完写 `status=window_exhausted`、`final_status=null`；
- 不进入 Redis completed/failed 永久终态队列；
- `continuation_eligible=true`、`next_round=历史最大合法Round+1`；
- 显式 resume 后由现有 feeder/GATE-FEED-ENQUEUE 入队；
- AI gave_up 不自动无意义重试，但题目可继续；
- 纯基础设施失败保留独立 Round 资产，不消耗数学窗口额度；
- 历史 `TRUNCATED_AT_MAX` 只兼容读取，默认 dry-run，不改生产数据。

## 二、核心设计

新增 `src/round_window.py` 纯领域模块，不连接 DB/Redis、不新增 Gate：

- `ensure_active_window`：开启/恢复窗口；窗口中途size保持稳定；
- `record_round_consumption`：区分数学Round和纯infra尝试；
- `exhaust_window_fields`：生成非永久窗口结束字段和历史；
- `pause_window_fields`：AI放弃等暂停但可继续；
- `resume_window_fields`：显式恢复prepared，保留legacy final证据；
- `next_absolute_round`：按历史最大合法Round+1，避免旧重复轮号覆盖资产。

窗口字段：

```text
round_window_id/status/start_round/size/rounds_used/started_at/ended_at/end_reason
round_window_history
continuation_eligible
next_round
```

`round_window_history` 当前记录已用完的窗口；完成窗口无需加入“未解窗口历史”。

## 四、Gate/行为流水

没有新增 Gate 或平行控制机制：

- 窗口内截断继续使用 `GATE-REQUEUE-TRUNCATED`；docstring检查改成
  `round_window_rounds_used < round_window_size`。
- 显式新窗口只把DB恢复prepared，实际入队使用 `GATE-FEED-ENQUEUE`。
- session回收继续 `GATE-KILL-SESSION`，新增reason=`window_exhausted`。
- 新flow：`round_window_started`、`round_window_exhausted`、`round_window_resumed`；
  AI放弃写`round_paused`，不写题目永久`run_failed`语义。
