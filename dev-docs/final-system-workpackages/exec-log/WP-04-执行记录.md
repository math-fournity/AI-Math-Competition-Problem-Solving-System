## 四、运行接口

### 归档临时资产

```bash
python -m src.formal_verification archive \
  --round-dir <round_dir> \
  --source <source> \
  --category formal \
  --target-name Main.lean
```

源文件必须存在、不是symlink、不含疑似secret；目标存在时拒绝覆盖。返回归档相对路径、
SHA-256、字节数和来源是否位于临时目录。缺失文件报错，不虚构通过。

### 执行可重跑命令

```bash
python -m src.formal_verification run \
  --round-dir <round_dir> \
  --run-name lean_main \
  --coverage-kind trusted_kernel \
  -- lean formal/Main.lean
```

不使用 shell；可执行文件通过 PATH，资产使用 Round 内相对路径。拒绝绝对路径、`..`、临时
路径依赖和疑似 secret 参数。子进程环境去掉 key/token/secret/password/credential 变量；
输出如命中 secret 形态会先脱敏。

### 结构检查与rounds_log

`inspect_formal_package(round_dir)` 返回直接事实，不给审计结论。
`formal_round_log_fields(round_dir)` 返回：

```text
formal_dir / formal_verification_path / formal_logs_dir / verification_dir
formal_source_paths / formal_run_record_paths
formal_structurally_complete / formal_all_runs_succeeded
formal_escape_hatches / formal_coverage_kinds
formal_requires_independent_audit=true
```

WP-02 负责在候选 proof 收尾时登记；WP-05 负责独立复制/重跑和充分性裁决。

## 五、最关键的语义分层

以下三项可以同时成立：

```text
structurally_complete = true
all_runs_succeeded = true
escape_hatches = {"formal/Main.lean": ["sorry"]}
```

真实 Lean 4.33.1 已验证这不是理论猜测：含 `sorry` 的 theorem 仍成功退出并给 warning。因此
本模块只保存事实；WP-05 必须检查命题等价性、关键 claim 覆盖、逃逸口和独立重跑，不能只
看退出码。

Python finite fixture 同理：运行成功且结构完整，但 coverage 只有 `finite_computation`，报告
明确只覆盖 `0 <= n <= 100`，没有无限归约依据，不得称为普遍证明。
