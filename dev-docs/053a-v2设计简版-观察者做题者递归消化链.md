## §0 一句话

取消主控整理者这个中间层：每轮ACP实例先以**观察者身份**消化前一现场（写出`分析笔记.md`），再以**做题者身份**继续探索（过程性写`工作笔记.md`）；主控不再生产任何认知内容，只做**编排、监督与提示词迭代**。

## §1 v1失败复盘——为什么需要v2

### 1.1 六轮数据

| 轮次 | 后端 | 结局 | 净进展 | 异常行为 |
|---|---|---|---|---|
| R1 | devin/glm-5-2 bare | 25000截断 | 框架+4解候选 | 纯thinking，无产出文件 |
| R2 | ox-alpha ACP max | 32000截断 | 两偶一奇Case C闭环 | 真实推进 |
| R3 | ox-alpha ACP | 32000截断 | 全奇结构建立 | 真实推进 |
| R4 | ox-alpha ACP | 32000截断 | α=1收尾+P1-P4归约 | 真实推进+一次自我纠错 |
| R5 | ox-alpha ACP | 32000截断 | α≥3未闭合 | **倒退：重验全偶**（禁令下仍发生） |
| 主控收尾 | 整理者本人 | 无预算限制 | α=3闭合；α≥5开放 | — |

### 1.2 三层根因（主控反思，用户质问"为什么它看不到你看到的"引出）

1. **有损压缩（表层）**：35万字符推理→几KB结论清单，压缩率200:1。裸结论无法区分"严格证明"与"上轮可能的错误"（R4内部就发生过猜想自我证伪）。
2. **重验是接手者的理性行为（中层）**：面对无推导的结论清单，唯一理性动作是重新推导再使用。"禁止重验"禁令与模型第一性倾向对抗，注定无效。
3. **任务粒度与认知模式错配（深层）**：v1把"理解全部历史+继续推进+写文件"三件事塞进同一实例同一回合。理解（观察模式）与生成（做题模式）在回合内打架——R5的倒退就是打架的表现。且主控的HANDOVER本身是有损中间层，引入双重代价：信息损失+信任税。

**关键自省**：主控能收尾而ACP不能，不是因为主控更聪明（同一个模型），而是因为主控（a）没有预算约束（b）看得到全部历史（c）没有产出压力。v1错误地把这三个优势的产物（摘要）当作可以直接喂给有约束实例的燃料。

## §2 核心设计：递归消化链

### 2.1 两份文档，职责分离

- **`工作笔记.md`**（每轮一份）：解题过程中的**自我记录**。推荐四节：已确认结论（附推导要点）/当前正在做/死路记录/下一步计划。要求"每完成一个推理块立即写入"——但允许烂尾：截断时没写进笔记的部分留在thinking里，由下一轮的分析笔记收殓。
- **`分析笔记.md`**（轮2起每轮一份）：**只针对紧邻前轮**（轮N-1）的独立理解重构。内容 = 前轮工作笔记 + 前轮thinking尾部（笔记最后一次更新之后、截断之前的进展）的整合。不做更早轮次的重复分析（递归链已覆盖）；若下钻更早档案发现错误或遗漏，记入文末"对更早档案的修正"节。

### 2.2 递归责任链

```
轮n的欠债只有一笔：轮n-1。
A(n) = 消化[ W(n-1) + tail(T(n-1)) ]     ——分析笔记
W(n) = 自己的探索过程记录                  ——工作笔记
T(n) = 本轮完整thinking（含未进笔记的尾部）——原始档案
```

信息像接力棒逐轮包装：越新的包装越厚（工作笔记+分析笔记双层），越老的内核越浓缩。原始trajectory永不删除——链条上任何一环被怀疑，随时下钻验证。**分析成本被递归摊薄**：轮N只欠一次分析，不欠全部历史。

### 2.3 尾部盲区的归属（本设计的关键洞察）

工作笔记是过程中写的，但**最后一次笔记更新与截断点之间还有一段最前沿的思考**——它只存在于trajectory尾部。这段"遗言"：
- 只有事后才能界定（截断发生在哪一刻，结束后才知道）——所以消化它必须是**下一轮的开场动作**，不能由任何人事前代劳；
- 是最新的、最珍贵的进展（往往正是卡点处的思路）；
- 通过工具的tail参数直接获取（见§5）。

## §3 完整流程逐轮走查

**轮1（纯做题者）**：读题 → 解题 → 过程中持续写工作笔记 → 截断（预期）或完成。产出：T1 + W1。

**轮2（观察者→做题者，两阶段）**：
- 拿到：T1原始档案 + W1 + 分析工具 + 空白现场。
- 先做（观察者）：读W1，用工具取T1尾部，写出A2——轮1工作状态终报。
- 再做（做题者）：基于**自己刚写的**A2继续解。无信任税——A2是它自己的理解。
- 截断 → 产出T2、W2。

**轮3（关键轮，"共同给到"机制）**：
- 拿到：A2（最新视图，prompt直入）+ W2 + 全量历史档案T1/T2（文件系统可及）+ 工具。
- 读A2恢复状态 → 读W2 → 取T2尾部 → 发现W2未记录的最新进展 → 写A3。
- 若对更早轮次细节有疑问（如"轮1方向X为何被排除"），**自主决定是否下钻T1**。
- 继续解题，写W3。

轮4+依此类推。梳理链A2→A3→A4是不断被最新实例刷新的认知主线；原始档案是永不丢失的底座。

**信息取舍权在接手者手里**：它自己决定钻多深——大纲层便宜，原文层按需付费。这是对v1"整理者替它决定什么重要"的根本纠正。

## §4 层次化工具：oc-trajectory skill

**位置**：`/Users/user/.config/opencode/skills/oc-trajectory/`（已安装进opencode全局skills，ACP实例自动可掌握；prompt模板中同时显式给出path双保险）

**设计范式**：照搬 `skills-devin/zcode-trajectory.md` + `scripts/zcode_traj.py` 的两层遍历模式（scan概览→idx定位→inspect下钻），适配opencode ACP的数据格式。

**数据源可靠性排序**（实测教训）：
1. `thoughts.jsonl`【主源】：ACP客户端实时逐chunk落盘，进程崩溃不丢。schema：`{"t":秒,"mid":id,"text":碎片}`。
2. `opencode_export.json`【不可依赖】：实测所有轮次均在65536字节处截断损坏（subprocess管道捕获限制）——acp_continue.py的已知bug。
3. `thinking.md`：主控从thoughts.jsonl拼接的纯文本，read/grep友好。

**截断指纹**（重要发现，已写入skill）：opencode撞单响应output上限（实测32000）时**stopReason仍报end_turn，无显式标记**。可靠指纹 = outputTokens为整数值 + 0 message chunk + 0 tool_call + thinking句中戛然而止。此状态命名为 **BUDGET_STARVED**，与TRUNCATED_AT_MAX（真死路候选）严格区分。

**工具命令**：
```bash
S=/Users/user/.config/opencode/skills/oc-trajectory/scripts/oc_traj.py
python3 $S scan   <thoughts.jsonl>        # 分段大纲：段号|行号|字符数|首句（转折词+2500硬切）
python3 $S tail   <thoughts.jsonl> 6000   # 末尾N字符——看前轮"最后的思考"
python3 $S search <thoughts.jsonl> '正则'  # 定位关键结论
python3 $S read   <thoughts.jsonl> <start> [chars]  # 按字符位下钻
```

## §5 提示词设计（两种轮次，只有两种）

模板文件：`v2/prompt_round1.md`（纯做题者）、`v2/prompt_roundN.md`（观察者→做题者，含{ROUND_NUM}/{PREV_NUM}占位符）。

### 5.1 轮1提示词要点
- "你是这道题的第一个解题者，在你之前没有任何人做过任何工作"
- 持续记录工作笔记（四节结构），**"写笔记的优先级高于多推一步算式"**
- 截断无须恐慌——只要笔记最新，后来者能接上
- 防作弊条款

### 5.2 轮N提示词要点（考古学叙事，用户口述原文收录）

> "这些是上一个AI探索这道题目最后的现场。你是轮次N，在你之前还有轮次1、轮次2……它们都对它们之前轮次的所有AI的工作trajectory和相关产出做了分析，都留下了分析笔记，也都留下了自己的工作笔记。所有的细节都在trajectory中，所有的笔记都在各轮次目录中。上一轮次的AI最后的思考，不在它的笔记中，在它的trajectory的最后的thinking中，你可以通过脚本的参数来直接拿到。但是你要注意，在它的工作笔记的最后更新和它的最后一次thinking之间，它可能还做了其他的事，所以它的笔记只是一个索引。"

任务顺序（严格）：
1. 写`分析笔记.md`：对轮N-1的工作笔记+thinking尾部的独立分析（更早轮次不重复——链条已覆盖；对更早档案的修正记文末专节）
2. 继续探索题目，过程中不断记录`工作笔记.md`
3. 截断无须担心："轮N+1会对你的工作笔记做你对N-1号AI的工作笔记做过的同一件事"
4. proof.md最终交付 + 防作弊条款

## §6 主控角色重定义

主控不再是认知生产者（不写HANDOVER、不代推数学），而是：

**监督清单（每轮检查）**：
1. 断言通过（model=ox-alpha / effort=max，回显校验，fail-fast）
2. 截断指纹识别（BUDGET_STARVED vs 其他终态）
3. 轮N≥2：分析笔记是否真实消化了尾部（抽查其对thinking尾部的引用准确性）
4. 工作笔记是否有过程性更新（而非结尾一次性补写）
5. 是否发生重验倒退（重验已闭环case的篇幅占比）
6. 提示词缺陷记录 → 迭代下一轮模板

**元循环**：监督发现 → 提示词修订 → 下一轮验证 → 再监督。主控的产出物是**更好的提示词**，不是数学内容。
