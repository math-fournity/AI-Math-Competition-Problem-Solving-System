## 0. 一句话

把并行会话实证的六条 SOP 修正落地到生产续传管线：解除"重验陷阱"对预算的消耗，
让每轮截断的思考以最小损失传导到下一轮。

## 1. 背景与证据

- 生产主路径（HANDOVER 摘要）实测压缩率 ~200:1（sim 样本 HANDOVER 仅 1038 字节）
- 三层根因：有损压缩 → 重验是接手者理性行为 → 任务粒度错配（详见 049§零）
- 后果佐证：039 失败池 153 道卡题；多轮续传的实际推进效率存疑

## 2. 改动内容

### 任务 1：CONTINUE_PROMPT_TEMPLATE 重写（观察者→做题者两阶段）

- Round N≥2 的 prompt 分两段任务：①先写 `分析笔记.md`（对 N-1 工作笔记+thinking
  尾部的独立消化）②再继续解题并过程性写 `工作笔记.md`
- 删除"不要重复已经做过的分析"禁令，代之以供料（推导链+负面知识）
- 增加预算配速段（告知本轮 output 预算实测特征）

### 任务 2：HANDOVER 生成升级（推导链式 + 负面知识）

- generate_handover 的摘要实例提示词按对方修正 1/3 重写：
  结论必须附推导链与验证锚点；显式记录已被证伪的猜想
- 保留 8 章节结构（续传规范文档不变），升级第 3/4 章的内容质量标准

### 任务 3：budget_starved 终态

- 指纹：纯 thinking 结束 + 0 message chunk + 0 tool_call + outputTokens==整数上限
- rounds_log/DB 状态新增 budget_starved，与 truncated_at_max 区分统计

### 任务 4：oc-trajectory 式工具移植

- scan/tail/search/read 四命令（照搬对方 oc_traj.py 模式适配我们的 jsonl 格式）
- 放 `scripts/traj_tool.py` + prompt 中给出用法——解题 AI 自助读取前轮档案
