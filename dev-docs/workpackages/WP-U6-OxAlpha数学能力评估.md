# WP-U6 — Ox Alpha 数学解题能力评估（默认管线的模型资格测试）

> **优先级**: 线 2（U2 之后；与 U4/U5 可并行）
> **依赖**: WP-U1（基线）、WP-U2（同题数据复用）
> **预计规模**: 评估实验（~10 题×2 模型）+ 评估报告（047）
> **性质**: 调查实验。红线：不改生产代码；配额纪律（免费也守 10 题上限）

---

## 0. 给执行 AI 的第一句话

Ox Alpha 是 coding/agentic 向的模型，**数学证明能力未知**——而它将被设为解题管线
的默认模型（037 决策）。你要做资格测试：同一批题（glm-5-2 有续传历史的真实题）
双模型对比跑，评估解题质量/reasoning 质量/提示词兼容性，回答"Ox Alpha 配不配当
默认解题模型"——不配则报告要说（037 的决策依据会因此修订，这比"配合演出"重要）。

## 1. 背景（为什么）

- 037 §4.2.12 列了评估维度（数学能力/reasoning 质量/1M context 利用/提示词兼容/
  tool calling 行为）；§2.2 决策理由 1-3 是免费+权限+session（**没有一条是数学能力**
  ——能力是被默认策略"顺带"的，必须补测）
- 系统的选题池准入 = 审计 Pipe 的 PASS（数学正确性）——模型不会解题 = 全链空转
- 已有对照组天然存在：glm-5-2 在同批题上的续传历史（DB rounds_log + proof 归档）

## 4. 任务分解

### 任务 1：出题清单（10 题分层抽样）

按 §2.2 的分布选题，输出清单表：题 ID / glm-5-2 历史终态 / 历史耗时 / 题源。

### 任务 2：批量实验脚本 `scripts/test_wp_u6_ox_alpha_eval.py`

复用 U1/U2 客户端：每题一次 OpenCode ACP 会话（同 INITIAL 提示词原文——兼容性
测试的第一层就是"不改编提示词直接喂"），全通知落盘 `tmp/wp_u6/<pid>.jsonl`，
组装出 message/proof 内容。**不跑 proof.md 写文件版**（评估阶段看 message 中的
证明即可——或者按提示词要求写 proof.md 到 work_dir 则检查它，二选一按实测行为）。

### 任务 3：五维评估（047 报告核心）

| 维度（037 原文） | 评估方法 | 判据 |
|---|---|---|
| 数学解题能力 | 10 题 boxed 答案正确率 vs glm-5-2 同题历史（人工判断或审计 Pipe 辅助——Master Agent 亲自核答案，10 题量级人工可行且符合适度依赖原则） | 正确率不低于 glm-5-2 历史 -15 个百分点（写明这是"可作默认"的底线判据，最终定夺留用户） |
| reasoning 质量 | thought 拼接的抽样阅读（3 题）：数学内容密度/幻觉/推理链完整度（对照 C1-C2 判断标准——SOP_04 的 C1/C2 描述可参考） | 无系统性幻觉；推理可读 |
| 1M context 利用 | 长题（选 1 道超长题干）跑一次看是否处理完整 | 不截断题干/能引用题干细节 |
| 提示词兼容 | 不改编注入的成功率：AI 是否按模板要求（写 proof/boxed/LaTeX/防作弊声明理解） | 10 题中 ≥8 题行为符合模板 |
| tool calling 行为 | 通知流 tool_call 统计：频率/kind 分布/与解题相关性（对照防作弊约束——有没有乱搜题） | 无违反防作弊约束的行为模式 |

### 任务 4：结论与建议（047）

三分支：**可作默认**（判据全过）/ **有条件默认**（如"先用于审计 Pipe/简单题，解题
管线再观察"）/ **暂不默认**（数学能力差距明显——建议 Devin ACP 反转为默认，交用户
修订 037 决策）。**诚实优先**——免费不是能力 substitute。

## 5. 禁止事项

- ❌ 10 题上限（失败重跑计次）；不跑 glm-5-2 对照（用历史数据）
- ❌ 评估不"放水"——判据先写后测（数据出来前本文档已定底线，防确认偏误）
- ❌ 不改生产代码/提示词模板（兼容性测试就要用原文）
- ❌ 答案核对不偷懒用"AI 自评"——Master Agent 亲自核或用标准答案字段
