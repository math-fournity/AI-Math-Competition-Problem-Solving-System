# 058 — 最终成品系统 Feature List 与需求追踪

> **性质**：用户需求的完整 Feature 冻结表；未来工作包必须引用 Feature ID
> **大图**：`057-最终成品系统大图与产品定义.md`
> **差距与路线**：`064-当前实现差距与实施路线总图.md`
> **原则**：Feature 完整不等于一次性全部实现；按工作包依赖逐步落地，禁止借机过度设计。

---

## 一、状态说明

- **目标**：最终系统必须具备的需求。
- **部分**：当前 repo 已有一部分，但语义或闭环不完整。
- **已有**：当前机制基本具备，后续只需适配新语义。
- **未有**：当前尚无可靠实现。
- 这里记录的是产品需求，不用“当前没实现”反向删除用户要求。

## 十四、需求变更纪律

1. 用户后续更新认知时，先更新本 Feature List 和 057 大图，再修改工作包。
2. 新需求必须判断是产品需求、实现方式还是暂时参数，不能混写。
3. `30` 是当前目标最大解题管线数量；实际 DB 并发值仍由用户决定。
4. key capacity 是配置能力，不预设永远为 1 或 2。
5. 默认 Round 数是窗口参数，不再建立总轮次永久失败语义。
6. 形式化充分性是最终正确门槛，不能被 `\boxed`、有限搜索或审计 AI 自述替代。
7. 新工作包必须列出覆盖的 Feature ID；未映射 Feature 不得被悄悄遗漏。
