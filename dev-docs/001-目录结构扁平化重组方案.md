# 目录结构扁平化重组方案

**日期**：2026-08-19
**性质**：方案文档——将 repo 目录结构从"嵌套子系统"扁平化为"统一分层"
**前置**：read-sync 已创建 README.md 引导地图（基于当前结构），重组后需同步更新

---

## §1 问题诊断

当前结构有5个问题：

1. **不必要嵌套**——repo 本身就是错题分析系统，代码却嵌在 `analysis-devin-failure-system/` 子目录里，多一层无意义路径
2. **命名不一致**——`analysis-devin-failure-system`（英文kebab）vs `AnalysisSystem开发`（中文混合），中文目录名在命令行/git/跨平台有隐患
3. **文档分散三处**——根 `docs/`（5个外移文档）+ 子系统 `docs/specs/templates`（16个）+ `AnalysisSystem开发/`（14个），职责重叠（根docs/AnalysisSystemDesign.md 和子系统docs/architecture.md 都讲架构）
4. **代码路径耦合**——`config.py` 硬编码 `PROJECT_ROOT / "analysis-devin-failure-system" / "templates"`，引用自己的模板要绕回根目录再进子系统
5. **命名不准确**——`AnalysisSystem开发/` 是工作包管理/需求追踪目录，不是"开发"本身

**设计原则**：
- 代码在根目录（src/monitoring/run_*.py），不再嵌套
- 文档统一在 docs/ 下按关注点分层（system/patterns/architecture/specs/templates）
- 脚本统一在 scripts/（合并三处）
- 开发管理用英文名 dev/（去中文）
- data/ 保持不动（代码依赖路径不变）

## §7 执行顺序

按依赖关系分6步：

### 步骤1：创建目标目录结构
```bash
mkdir -p docs/system docs/patterns docs/architecture docs/specs docs/templates
```

### 步骤2：git mv 移动文件
按§3的迁移清单，用 git mv 逐个移动（保留git历史）。先移代码，再移文档，最后移开发目录。

### 步骤3：修改代码路径常量
按§4的清单修改6个Python文件中的路径常量。

### 步骤4：写替换脚本并批量更新文档引用
写 `scripts/refactor_paths.py`，执行§5.1的13条替换规则。

### 步骤5：更新 README.md 和 AGENTS.md
按§6手动更新引导地图和索引（结构变化大，脚本替换不够，需要手动调整分组）。

### 步骤6：验证
1. `python -c "from src.config import PROJECT_ROOT; print(PROJECT_ROOT)"` — 确认路径常量正确
2. `python -c "from src.continuation_config import CONTINUE_SPEC; print(CONTINUE_SPEC.exists())"` — 确认续传规范文档路径正确
3. `python -c "from monitoring.continuation_control import PROJECT_ROOT; print(PROJECT_ROOT)"` — 确认monitoring路径正确
4. `grep -r "analysis-devin-failure-system" *.md docs/ dev/` — 确认文档中无残留旧路径
5. `grep -r "AnalysisSystem开发" *.md docs/ dev/` — 确认无残留中文目录名
6. `grep -r "analysis-devin-failure-system" src/ monitoring/ scripts/` — 确认代码中无残留旧路径

### 步骤7：commit
分2-3个commit：
1. `git mv 移动文件（代码+文档+开发目录）`
2. `修改代码路径常量（PROJECT_ROOT/ANALYSIS_ROOT/模板路径）`
3. `批量更新文档引用路径+更新README.md引导地图`

## §8 风险与回滚

### 风险
1. **482处文档引用**——批量替换可能遗漏或误替换。缓解：替换脚本输出报告，人工抽查
2. **代码路径常量**——6个文件修改，PROJECT_ROOT 层数变化可能导致路径错误。缓解：步骤6验证
3. **git history**——git mv 保留历史，但如果移动后立即修改文件，diff可能不连续。缓解：移动和修改分commit

### 回滚
如果验证失败：
```bash
git revert HEAD~3..HEAD  # 回滚3个commit
```
或在步骤2-3之间发现问题，直接 `git checkout -- .` 回到移动前状态。
