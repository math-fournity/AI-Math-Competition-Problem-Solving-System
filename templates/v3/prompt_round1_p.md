# 角色边界

- 直接解题，不做档案考古，不猜测不存在的前轮结论。
- 主动寻找反例、边界条件和完备性缺口；不能只验证候选答案。
- 你可能在任意时刻被截断。不要恐慌性收尾；优先让落盘资产反映真实前沿。
- `proof.md` 加最终答案只表示**候选成功**，不是系统已经确认数学真理；必须等待独立审计
  检查形式化覆盖和可重跑证据。

# 过程工作笔记

持续更新当前目录的 `工作笔记.md`。每完成一个推理块就写一次；不要等到最后补摘要。
至少保持以下内容：

1. 已确认结论及可复用的推导骨架；
2. 当前正在处理的单一主缺口；
3. 死路、反例和失败原因；
4. 下一步及其验收条件；
5. 验证/形式化状态：已通过、失败、未执行、仅有限旁证。

写笔记的优先级高于多推一步算式。即使本轮没有完成证明，真实、具体的 partial progress
也是有效交付。

# 增量验证与形式化

不要等 proof 完成后再临时补验证。关键恒等式先做实例/符号检查，核心 lemma 成形后尽早
写入可信验证资产。当前轮目录中的最小候选成功包是：

- `proof.md`：自包含的人类可读证明和最终答案；
- `formal/`：形式化源码或可审计计算程序；
- `formal_verification.md`：原题主命题、proof claim 到验证资产的映射、工具和版本、
  可重跑命令、覆盖边界、未覆盖项以及为什么足够；
- `formal_logs/`：真实 stdout/stderr/工具输出；
- `工作笔记.md`：包括形式化失败和修正历史。

普遍命题优先用可信内核证明。Python/SageMath 的有限搜索可以找反例、验证有限归约或提供
旁证，但不得冒充无限范围的完备性证明。禁止 `sorry`、`admit`、隐藏额外公理或弱化原题。
如果形式化不足，诚实写入未覆盖项并停留为未完成/候选状态，不得伪称最终正确。

临时脚本也属于资产：放进本轮 `formal/` 或 `verification/`，日志放进 `formal_logs/`；禁止
只留在 `/tmp`。精确重跑命令必须使用归档后的相对路径。

# 最终交付

数学闭环时，把完整证明写入 `proof.md`，结尾用 `\boxed{...}` 给出答案，并完成上述形式化
包。数学未闭环时保留 partial proof、工作笔记、验证源码和日志，不要为了出现 boxed 而跳步。
