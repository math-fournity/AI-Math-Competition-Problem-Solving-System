## 二、AI 的理解

### 2.1 核心洞察：认知闭包和认知包都是特殊的 view

用户指出认知闭包的本质是一个**特殊的 view**——它不是 repo 中已有的视角（源码/设计/需求/运行操作），而是**为某个具体工作包临时构建的视角**。这个视角的内容是该工作包所需的全部认知（N），组织形态是综述论文。

**用户补充的关键澄清**：认知包 n[x]（008 中的迭代候选集）和认知闭包 N（收敛后的最终版）是同一个东西的不同代。n[x] 是逼近过程中的候选版，N 是收敛后的最终版。因此**认知包也是特殊的 view**——它是尚未收敛的认知闭包，是同一类文档的不同代际状态。

这意味着认知闭包、认知包和现有看法文件（views/）都是同类事物——都是 view——但有关键区别：

| | 现有看法文件（views/） | 认知包 n[x]（迭代中） | 认知闭包 N（收敛后） |
|---|---|---|---|
| 构建时机 | 长期维护，项目演进中持续更新 | 为某个工作包临时构建，迭代中 | 为某个工作包临时构建，已收敛 |
| 覆盖范围 | 一种分类法下的所有文档/代码 | 一个工作包所需的候选认知（跨分类法） | 一个工作包所需的全部认知（跨分类法） |
| 持久性 | 长期存在 | 持久化，跨 session 传递，每代 diff 可追踪 | 工作包完成后归档 |
| 视角 | 单一视角（源码/设计/需求/...） | 跨视角（按工作包需要混合多种视角） | 跨视角（按工作包需要混合多种视角） |
| 稳定性 | 稳定（长期维护） | 不稳定（每代可能变化，非单调） | 稳定（收敛，不再变化） |
| 文档形态 | 看法文件格式 | **面相3（综述论文体例）** | **面相3（综述论文体例）** |

认知闭包和认知包都是"跨视角的、为具体任务定制的 view"。区别只在收敛状态——n[x] 尚未收敛（候选集还在进出变化），N 已收敛（候选集稳定）。但两者的文档形态相同，都是面相3。

### 2.2 三种面相

用户给出了认知闭包与认知包的三种面相（文档形态）。三种面相同时适用于认知包 n[x]（迭代中）和认知闭包 N（收敛后）——区别只在内容是否稳定，不在文档形态：

**面相1：纯索引（xpath 列表）**
- 内容：`[1] monitoring/continuation_control.py::start`、`[2] docs/specs/p27_monitor_spec.md#A类检查项`、...
- 本质：闭包的**骨架**
- 优点：极小、可机器处理、可 diff、可和 trace.csv 交叉验证
- 缺点：不是认知——AI 拿到一串 xpath 仍然要逐个加载才知道内容是什么。它是闭包的骨架，不是闭包的肉

**面相2：纯摘录（所有元素直接叙述）**
- 内容：把每个 xpath 指向的函数体/章节内容直接复制进来，组织成连贯叙述
- 本质：闭包的**肉**
- 优点：自包含——AI 加载这一个文档就拿到了全部认知，不需要再加载原始文件
- 缺点：大（等于 N 的全文）、冗余（repo 里已有这些内容，这里又复制一份）、易过时（原始文件改了，摘录没同步）

**面相3：综述论文（引用+正文+参考文献列表）**
- 内容：正文是带引用标记的论述（"X 做的是……[1]，Y 规定的是……[2]，X 实现了 Y[3]"），正文后是参考文献列表（`[1] path::function`、`[2] path#section`、`[3] trace.csv 第 N 行`）
- 本质：**骨架+肉+关系论述**
- 优点：既是认知（正文论述让 AI 理解关系和含义），又是索引（参考文献列表可交叉验证），还不过大（正文是提炼不是复制）
- 缺点：写作成本高（要写论述，不只是列引用）

### 2.3 三种面相的递进关系

这不是三个并列选项，是**同一闭包的三个抽象层级**：

```
面相1（纯索引）= 闭包的骨架
  → 可机器验证，但不是认知
  ↓ 加上内容叙述
面相2（纯摘录）= 闭包的肉
  → 是认知且自包含，但冗余且易过时
  ↓ 把复制改为引用+论述
面相3（综述）= 骨架+肉+关系论述
  → 是认知、可验证、不过大
```

面相3 是面相1 和面相2 的**综合**——它有面相1 的索引（参考文献列表）和面相2 的认知（正文论述），但用引用替代了复制，避免了面相2 的冗余和过时。

### 2.4 面相3 的结构精确化

用户说"inline 中是引用的 ID，正文之后是所有被序号化、带有 ID 的 XPATH 的列表"——这就是学术论文的引用结构：

```
# 认知闭包：<工作包标题>

## 正文

做这个工作包，需要理解续传控制的核心逻辑。ContinuationControl.start[1]
负责启动续传流程，它调用了 ContinuationControl.feed[2] 来注入任务。
start 的行为由 p27_monitor_spec.md 的 A 类检查项[3] 规定，
两者是 implements 关系[4]。

执行时还需要理解 stall 检测机制。stall 检测在 watch_dog[5] 中实现，
它依赖 rate limit 配置[6]……

## 参考文献

[1] monitoring/continuation_control.py::ContinuationControl.start
[2] monitoring/continuation_control.py::ContinuationControl.feed
[3] docs/specs/p27_monitor_spec.md#A类检查项
[4] trace.csv 第 12 行（implements 关系）
[5] monitoring/continuation_watchdog.py::watch_dog
[6] src/config.py::RATE_LIMIT
```

这个结构的精妙之处：

1. **正文是论述不是复制**——AI 读了正文就理解了"这些元素之间什么关系、为什么在这个闭包里"，不需要逐个加载原始文件再自己推断关系
2. **参考文献列表是索引**——可和 trace.csv 交叉验证（参考文献里的 xpath 是否都在 trace 的闭包遍历结果里？）
3. **引用 ID 是审计锚点**——正文中每个论断都能追溯到具体 xpath，满足 006 §2.4 的可审计性
4. **序号化让引用稳定**——[1][2][3] 是稳定的引用 ID，即使正文修改，参考文献列表的序号不变

## 三、面相3 作为认知闭包的标准形态

### 3.1 为什么面相3 是标准形态

| 要求 | 面相1 | 面相2 | 面相3 |
|---|---|---|---|
| 是认知（AI 读了能理解） | ✗（只是路径列表） | ✓（有内容） | ✓（有论述） |
| 可审计（每条认知有出处） | ✓（就是 xpath） | ✗（内容复制进来，出处不显式） | ✓（引用 ID 指向 xpath） |
| 不过大（不冗余复制） | ✓（极小） | ✗（复制全文） | ✓（正文是提炼，引用替代复制） |
| 可验证（和 trace 交叉验证） | ✓（直接对比 xpath 集合） | ✗（内容难以自动验证） | ✓（参考文献列表可对比） |
| 表达关系（元素之间什么关系） | ✗（只有路径，无关系） | 部分（叙述中可能隐含关系） | ✓（正文显式论述关系） |

面相3 是唯一同时满足所有要求的面相。面相1 缺"是认知"和"表达关系"；面相2 缺"可审计""不过大""可验证"。

### 3.2 面相1 和面相2 的用途

虽然面相3 是标准形态，面相1 和面相2 有各自用途：

- **面相1（纯索引）**：作为面相3 的**参考文献列表部分**。也是机器验证的接口——闭包遍历算法输出的就是面相1，AI 据此写面相3 的正文。
- **面相2（纯摘录）**：作为**工作执行时的加载清单**——AI 执行工作包时，按参考文献列表加载原始文件（相当于临时构造面相2），在面相3 正文的认知指导下工作。

三者协作：
```
闭包遍历算法 → 输出面相1（xpath 列表）
  ↓
AI 基于面相1 + 加载原始内容 → 写出面相3（综述论文）
  ↓
AI 执行工作包时 → 按面相3 的参考文献列表加载原始文件（临时构造面相2）
  ↓
在面相3 正文的认知指导下工作
```

## 四、对 006-010 的影响

### 4.1 对 006（认知闭包概念定义）

**直接回答 006 §2.9 开放问题 #4（闭包文档的模板）**——面相3 就是模板。模板结构：
- 标题：`# 认知闭包：<工作包标题>`（收敛后）或 `# 认知包 n[x]：<工作包标题>`（迭代中）
- 正文：带引用 ID 的论述（每个论断引一个 xpath）
- 参考文献：序号化 xpath 列表

**修正 006 §2.5**——006 §2.5 说工作包 README.md 应该是"带引用的认知论述"，但没给出精确结构。本文档给出精确结构：正文（带引用 ID 的论述）+ 参考文献（序号化 xpath 列表）。这是学术论文体例，不是随意带引用的论述。

### 4.2 对 007（闭包获取的工程优化）

面相3 的参考文献列表就是 N 的精确表达——**N = 参考文献列表的 xpath 集合**。最小 M 的"最小"可以定义为"恰好包含参考文献列表所有 xpath 指向的内容"。

面相1 是闭包遍历算法的直接输出——算法计算出 N 的 xpath 集合，就是面相1。AI 据此写面相3 的正文。

### 4.3 对 008（认知动力过程）——认知包和认知闭包共用面相3

**认知包 n[x] 和认知闭包 N 共用面相3 文档形态**——这是本文档的关键澄清。n[x] 不是一种不同于 N 的文档，它是 N 的前身，用同一形态。

认知包 n[x] 的每一代就是一份面相3 文档：
- 正文是"我认为 N 包含这些，因为……"（当前代的假设论述）
- 参考文献是当前代的 xpath 候选集

认知闭包 N 就是收敛后的面相3 文档：
- 正文是"这个工作包需要这些认知，因为……"（稳定的论述，不再变化）
- 参考文献是稳定的 xpath 集合（不再进出）

**从 n[x] 到 N 的演化就是面相3 文档的代际 diff**：
- xpath 的进出 → 参考文献列表变化（哪些加入了、哪些移除了）
- 论述的修正 → 正文变化（对关系的理解如何演进）
- 收敛 → 正文和参考文献列表都不再变化，n[x] = N

这意味着认知动力过程（008）的持久化机制就是**一份面相3 文档的 git 版本历史**——每代 n[x] 是一个 commit，git diff 显示代际变化，最终收敛的 commit 就是 N。不需要为认知包发明新的文档格式，面相3 就是认知包的格式。

这和 008 §四（非单调性）一致——"进进出出"直接体现为参考文献列表的代际 diff，"纳入/排除理由"写在正文中。

### 4.4 对 009（孤岛认知危机）

面相3 的参考文献列表可用于**孤岛检测**——如果参考文献列表中的 xpath 只覆盖了某些目录（岛屿），而递归 README 遍历发现还有其他相关岛屿，说明闭包不完备（009 的孤岛认知危机）。

### 4.5 对 010（trace 幂等的实用边界）

参考文献列表的 xpath 粒度受 010 粒度决策约束：
- xpath 到函数/章节级，不到行级
- xpath 到 DB 表级，不到记录级
- 例外（如特定 batch 运行记录）可到记录级

参考文献列表的 xpath 集合 = N = 在实用粒度上的闭包成员。

## 五、面相3 和现有体系的关系

### 5.1 和工作包 README.md 的关系

认知闭包（面相3）是工作包 README.md 的**核心组成部分**，或就是工作包 README.md 本身。

现有工作包 README.md（akash.md 阶段3）列的是：

- 甚至直接列出需要加载的具体文档和代码

- **认知闭包正文**（带引用 ID 的论述——为什么这些认知在这个闭包里，它们之间什么关系）
- **参考文献列表**（序号化 xpath——N 的精确表达）
- 验收标准

### 5.2 和看法文件（views/）的关系

认知闭包是**特殊的 view**（§2.1）——跨视角的、为具体任务定制的 view。它和现有看法文件的关系：

- 现有看法文件是**认知闭包的原料来源**——闭包遍历时通过看法文件导航到相关文档
- 认知闭包是**跨视角的合成**——一个闭包可能同时引用源码视角、设计视角、需求视角的文档
- 现有看法文件是**长期维护的**，认知闭包是**临时构建的**

### 5.3 和 view-index.csv 的关系

认知闭包的面相1（参考文献列表）可以录入 view-index.csv，作为一种特殊的 view：

这样闭包成员可被 view-index.csv 查询，和现有看法文件统一管理。

## 六、面相3 的写作流程

### 6.1 从面相1 到面相3

```
1. 闭包遍历算法（或认知动力过程收敛）输出面相1（xpath 列表）
2. AI 加载面相1 中每个 xpath 指向的原始内容
3. AI 理解这些内容之间的关系（利用 trace 关系图 + 自己的理解）
4. AI 写正文：用论述表达这些关系，每个论断引一个 xpath 作为引用 ID
5. AI 编参考文献列表：把面相1 的 xpath 序号化
6. 输出面相3（综述论文）
```

### 6.2 写作约束

- **正文每个论断必须有引用**——不能有"裸论断"（没有出处的断言）。这和综述论文的引用规范一致。
- **参考文献列表必须和正文引用一致**——正文中引用的 ID 必须在参考文献列表中有对应条目；参考文献列表中的条目必须在正文中被引用。这和学术论文的引用一致性要求一致。
- **正文是论述不是复制**——不能把原始内容复制到正文。正文是 AI 对关系的理解和叙述，引用指向原始内容。
- **参考文献列表的 xpath 粒度遵循 010**——到函数/章节级，不到行级；到 DB 表级，不到记录级。

## 七、开放问题

1. **引用 ID 的格式**——`[1]` 还是 `[MON-A1-01]`（含工作包编号）？前者简洁但跨闭包不唯一；后者唯一但冗长。可能需要闭包内唯一 + 闭包间通过文件名区分。
2. **面相3 的版本管理**——认知动力过程（008）中每代 n[x] 是一份面相3。如何管理多版本？git 追踪每代变化？还是只保留最终收敛版 + 审计 trail？
3. **面相3 和 trace.csv 的自动交叉验证**——能否实现工具自动对比面相3 的参考文献列表和 trace 闭包遍历结果，检测不一致？
4. **面相3 的正文写作质量标准**——"论述"的详细程度如何？一句话引用还是一段话解释？可能需要按角色区分（执行 AI 需要详细论述，审计 AI 只需索引）。
5. **面相2 的临时构造**——§3.2 说执行时按参考文献列表加载原始文件相当于临时构造面相2。这个"临时构造"是否需要显式化？还是 AI 自然地按需加载即可？
