## §1 问题背景

### 1.1 v1方案的问题

POC-2.6续传机制的v1方案是机械拼接reasoning_content——把被截断AI的thinking dump给下一个AI。这在CC-101_bare/vein上成功了（Round 1只有1个agent step，全部是thinking），但在CC-103_bare上失败了：

- CC-103_bare Round 1有6个agent step（web_search + 多轮thinking）
- 完整内容221K字符（reasoning 137K + tool_calls 1.8K + observation 82K）
- v1方案只传了最后一个step的reasoning_content（66K，30%）
- 丢失了前5步的全部上下文——AI做了什么web search、得到了什么结果
- Round 2的81K thinking全在计划写代码但从未写出——因为AI不知道自己之前已经搜索到了关键论文

### 1.2 核心认知转变

续传不是"拼接thinking"，是"交接研究"。像数学家交接研究笔记——不是把草稿纸原样递给下一个人（上面有涂改、死胡同、重复），而是整理成清晰的研究文档，让接手的人快速定位"已知什么"、"卡在哪"、"该试什么"。

## §2 交接文档（HANDOFF.md）标准结构

### 2.1 八个必填章节

```markdown
# 交接文档 · {problem_name} · Round {N}-{M} 探索历程

> **交接给**：下一个AI，请在此基础上继续完成解答
> **来源**：{problem_name} Round {N}（{X}个agent step）+ Round {M}（{Y}个agent step，被截断）
> **制作时间**：{date}

---

## 1. 题目
{原始问题文本}

## 2. 答案猜想
{当前最佳猜想及置信度。如果猜想被推翻过，记录演变过程。}

## 3. 已确认的结论
{带推导概要的数学事实。不是原始thinking，是提炼后的结论。每条结论标注来源（哪一轮哪个step）。}

## 4. 已尝试的方向
{走了哪些路线、成功/失败/未完成。每条路线标注：方向描述、结果、原因。}

## 5. 关键文献
{搜索到的论文、定理、已知结果。记录论文URL、关键定理内容、对本题的作用。}

## 6. 已有的中间产物
{脚本、计算结果、文件。每个产物记录路径和功能。如果没有任何产物，明确说明。}

## 7. 当前卡在哪里
{截断时正在做什么、遇到了什么困难。为什么卡住的分析。}

## 8. 建议的下一步
{从已有发现看该试什么。具体的、可执行的步骤。}

## 附录：探索历程时间线
{每轮每个step的简要描述。}
```

### 2.2 章节填写要求

- **§3 已确认的结论**：每条结论必须是独立的数学事实，带推导概要（不是完整推导，是关键步骤）。如果结论被推翻，保留被推翻的结论并标注"已被§X推翻"。
- **§4 已尝试的方向**：每条方向标注结果（✅成功/❌失败/⚠️未完成）。失败的方向要记录失败原因——避免下一个AI走同样的死胡同。
- **§5 关键文献**：如果PDF无法读取，明确标注"PDF不可读"，但记录从搜索摘要中获取的信息。
- **§6 已有的中间产物**：如果没有任何产物（所有分析都在thinking中），明确说明"Round X-Y没有写出任何脚本或文件"。
- **§7 当前卡在哪里**：不是"AI被截断了"（这是显然的），而是"AI在做什么时被截断了、为什么这个任务困难"。
- **§8 建议的下一步**：必须是具体的、可执行的步骤。不是"继续思考"，而是"写Python脚本用z3检查7×7网格上是否存在3-着色避免所有同色面积-3三角形"。

## §3 从export中提取什么

### 3.1 提取规则

| 来源 | 提取 | 不提取 |
|---|---|---|
| thinking spin (reasoning_content) | 确认的数学结论、猜想、证明策略、关键计算结果、死胡同及原因 | 重复推理、元评论("let me think")、已纠正的错误细节、中间计算过程 |
| tool calls | web search的关键发现、写的脚本及运行结果、创建的文件 | 失败的搜索、无关的搜索、重复的搜索 |
| observation | 论文定理、计算验证结果、搜索到的关键信息 | 无关的搜索结果全文、PDF原始二进制 |

### 3.2 多agent step的处理

一个round可能有多个agent step（如CC-103_bare Round 1有6个）。提取时：

1. **按step顺序处理**——step0的thinking可能包含初始分析方向，step5的thinking可能包含最终结论
2. **每个step提取关键信息**——不是只看最后一个step
3. **跨step关联**——step0搜索到的论文在step5的thinking中被引用，交接文档中应该关联起来
4. **tool calls和observation配对**——step0的web_search和它的observation是一对，提取时一起看

### 3.3 多round的累积

交接文档是累积的——每轮续传后更新，不是重写：

- Round 1-2的交接文档 → Round 3续传 → Round 3被截断 → 更新交接文档为Round 1-3的版本 → Round 4续传
- 每次更新时，在§3添加新确认的结论、§4添加新尝试的方向、§6添加新写的脚本、§7更新卡点、§8更新建议

### 3.4 v1方案失败轮次的特殊处理（2026-08-18补充）

当从v1方案（机械拼接reasoning_content）切换到v2方案（交接文档）时，可能面临v1已经跑了多轮的情况。处理原则：

1. **v1的Round 1是原始数据**——Round 1是AI从原始prompt开始的第一次探索，thinking内容最完整。提取时以Round 1为主。
2. **v1的Round 2如果有tool calls**——Round 2可能做了web search或写了脚本，这些tool calls和observation是有效内容，必须提取。即使v1的续传prompt只传了reasoning_content，Round 2的export中仍然记录了完整的tool calls和observation。
3. **v1的Round 3+如果纯thinking spin**——如果Round 3+每轮只有1个agent step（纯thinking，0个tool calls），且内容是重复"重新发现"之前的结论，这些轮次的有效信息很少。提取时只需确认"这些轮次没有新发现，AI在重复打转"。
4. **v1续传prompt本身不需要提取**——v1的续传prompt（拼接的reasoning_content）不是AI的探索内容，是脚本构造的输入，不需要纳入交接文档。

**实例**：CC-103_vein跑了5轮v1续传。Round 1（66K thinking）和Round 2（18个agent step，含大量web search + 30K和48K的thinking分析）是有效内容的主要来源。Round 3-5（各1个agent step，纯thinking spin，重复"重新发现"下界S≥3）几乎没有新信息。交接文档以Round 1-2为主，Round 3-5只在附录中记录"无新发现，AI在重复打转"。

### 3.5 交接文档可以委托subagent制作（2026-08-18补充）

交接文档的制作可以委托给subagent并行完成——Master Agent读取export提取关键信息，把信息整理成subagent的task prompt，subagent按§2标准结构写HANDOFF.md。这样多个run的交接文档可以并行制作。

**Master Agent需要提供给subagent的信息**：
- 题目文本
- 每轮的agent step数量和关键指标（rc/msg/tc/comp）
- 每个step的thinking开头和结尾（关键结论和卡点）
- tool calls的函数名和关键参数（web search的query、写的脚本名）
- observation的关键内容（搜索到的论文、计算结果）
- 已有的中间产物（脚本文件名和功能）
- AI的答案猜想和置信度
- 当前卡在哪里的分析
- 建议的下一步

**subagent不需要读export**——Master Agent已经提取了关键信息，subagent只需要按标准结构组织成文档。

## §4 循环操作流程

```
┌─────────────────────────────────────────────────┐
│  1. 启动AI（devin -p --prompt-file ... --export ...）  │
│     prompt = 题目 + "请先读取HANDOFF.md"          │
└──────────────────────┬──────────────────────────┘
                       ▼
              2. AI运行（thinking + working）
                       │
                       ▼
              3. AI退出（完成或被截断）
                       │
                       ▼
              4. 检测export
                 ┌────┴────┐
                 │         │
            completed   truncated
                 │         │
                 ▼         ▼
            ✅完成    5. 读取完整export
            写proof.md   （所有agent step的thinking+tool_calls+observation）
                         │
                         ▼
                      6. 更新HANDOFF.md
                         （添加本轮新发现）
                         │
                         ▼
                      7. 构造下一轮prompt
                         （题目 + "请先读取HANDOFF.md"）
                         │
                         ▼
                      → 回到步骤1
```

### 4.1 检测截断的判定

```python
def is_truncated(export_path):
    # 加载最后一个agent step
    step = get_last_agent_step(export_path)
    rc = len(step.get("reasoning_content", "") or "")
    msg = len(step.get("message", "") or "")
    tc = len(step.get("tool_calls", []) or [])
    comp = (step.get("metrics", {}) or {}).get("completion_tokens", 0)
    
    # 截断：有thinking但没有working产出，且completion_tokens接近上限
    truncated = rc > 0 and msg == 0 and tc == 0 and comp >= 24000
    return truncated
```

### 4.2 完成的判定

```python
def is_completed(export_path):
    step = get_last_agent_step(export_path)
    msg = len(step.get("message", "") or "")
    tc = len(step.get("tool_calls", []) or [])
    # 完成：有working产出（message或tool_calls）
    return msg > 0 or tc > 0
```

### 4.3 续传prompt模板

```
你是数学大师。请解答以下数学题。

题目（{problem_id}）：
{原始问题文本}

=== 之前的探索历程 ===

之前的AI已经对这道题做了大量探索（{N}轮thinking），但因为输出长度限制被截断了。

工作目录中有一份交接文档 HANDOFF.md，是之前AI完整探索历程的整理。请先用 read 工具读取 HANDOFF.md，了解：
- 已确认的结论
- 已尝试的方向
- 关键文献
- 当前卡在哪里
- 建议的下一步

然后在 HANDOFF.md 的基础上**继续**完成解答，不要从头开始。

要求：
1. 在之前的探索基础上继续，不要重复已经做过的分析
2. 给出完整的解答过程
3. 最终答案用 \boxed{答案} 格式给出
4. 数学公式用LaTeX
5. 把证明写到proof.md文件中，不要在对话里输出完整证明
```

## §5 与v1方案的对比

| 维度 | v1（机械拼接） | v2（交接文档） |
|---|---|---|
| 传什么 | 最后一个step的reasoning_content | 从所有step提取的有效内容整理成结构化文档 |
| 内容完整度 | 30%（CC-103_bare案例） | ~100%（thinking+tool_calls+observation的有效信息都提取） |
| AI接手效率 | 低——要重新理解原始thinking中的涂改和死胡同 | 高——直接定位"已知什么"、"卡在哪"、"该试什么" |
| 多step处理 | 只取最后一个step | 所有step按顺序提取，跨step关联 |
| 多round累积 | 拼接所有round的reasoning（越来越长） | 更新交接文档（保持结构化，不无限增长） |
| 自动化程度 | 已自动化（continue_solver.py） | 目前手动，后续可自动化 |

## §6 自动化路径

交接文档的整理目前是Master Agent手动做的。后续可自动化为：

1. **脚本自动化**：写一个脚本，用正则/规则从export中提取关键信息，按模板生成HANDOFF.md。适用于结构化程度高的export（如web_search结果、脚本运行结果容易提取）。
2. **AI自动化**：让一个AI（subagent）读export，按§2标准生成HANDOFF.md。适用于thinking中有效内容需要理解才能提取的情况。
3. **混合方案**：脚本提取tool_calls和observation（结构化部分），AI提取thinking中的有效内容（需要理解的部分）。

**推荐**：先用混合方案——脚本做机械提取，AI做理解提取。脚本提取的部分作为AI的输入，AI只需要理解thinking部分。

## §7 适用范围

交接文档方案不仅适用于POC-2.5/2.6的续传场景，适用于任何AI因completion_tokens限制被截断需要续传的情况：

- **竞赛数学解题**：AI在thinking spin中被截断（当前POC-2.5/2.6的场景）
- **长证明验证**：AI在验证长证明时thinking过长被截断
- **复杂代码实现**：AI在规划复杂代码时thinking过长被截断
- **文献调研**：AI在分析多篇论文时thinking过长被截断

任何使用thinking模型的系统，遇到长thinking spin撞上completion_tokens上限时，都可以用交接文档方案续传。
